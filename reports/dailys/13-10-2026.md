## 3. Hướng dẫn test API bằng Postman

Đã hướng dẫn theo luồng cụ thể của hệ thống:

1. Khởi động PostgreSQL và backend local.
2. Tạo Environment với `base_url`, `access_token`, `refresh_token` và ID tài khoản thử nghiệm.
3. Import OpenAPI từ `/openapi.json`, gửi JSON bằng Body raw và thiết lập Bearer Token.
4. Kiểm tra health, đăng nhập admin và tự lưu token bằng Post-response script.
5. Gọi `/auth/me`, danh sách tài khoản, tạo sinh viên, sửa hồ sơ, khóa/mở khóa và reset password.
6. Đăng nhập sinh viên bằng MSSV, kiểm tra hồ sơ, học phần, nhiệm vụ và quyền truy cập API admin.
7. Gọi dự báo độc lập với đầy đủ 17 đặc trưng và kiểm tra cấu trúc kết quả.
8. Kiểm tra lỗi xác thực, sai vai trò, dữ liệu thiếu/sai và ID không hợp lệ.

Đã giải thích các điểm dễ nhầm: login nhận JSON thay vì OAuth2 form; access token khác refresh token; `confidence` là xác suất lớp nguy cơ; health hiện không kiểm tra DB; danh sách rỗng của tài khoản mới có thể là kết quả hợp lệ. Hướng dẫn Postman được đối chiếu với tài liệu chính thức về import OpenAPI và biến môi trường.

Đây là hướng dẫn và mẫu request/assertion, không phải kết quả đã thao tác thành công toàn bộ API trên Postman.

## 5. Kết quả phân tích và đánh giá

### 5.1. Điểm mạnh

- Backend có cấu trúc module phù hợp với hệ thống khóa luận, phân tách router, schema, ORM, repository, service và ML.
- Có JWT access/refresh token, kiểm tra trạng thái và vai trò hiện tại từ DB.
- Response tài khoản không trả password hash; reset password không ghi mật khẩu vào audit.
- Nhiều API sinh viên, cố vấn và giảng viên đã kiểm tra sở hữu dữ liệu.
- Database có quan hệ nghiệp vụ rõ, UUID, khóa ngoại, unique, JSONB và index.
- Có unit/mock test và các kịch bản kiểm thử nghiệp vụ để tiếp tục hoàn thiện.
